## 一、项目概述

### 1.1 项目背景与意义

近年来，儿童青少年心理健康问题日益受到社会关注。中小学生受限于认知与表达能力，常常无法向家长或教师准确表达内心的压力、焦虑甚至危机信号。传统心理辅导存在专业人才不足、发现滞后、覆盖面有限等问题。

本课程设计以"**早发现、早干预**"为目标，设计并实现了一套 **MindIsle（心屿）学生心理安全评估与多智能体陪伴系统**：学生以文字倾诉为入口，系统实时评估心理风险并分级响应——低风险给予共情陪伴，中风险叠加认知行为（CBT）疏导，较高风险加入情景演练并通知教师，高危风险立即触发"一票否决"并展示 24 小时心理援助热线。系统遵循**北邮 ACPs（Agent Collaboration Protocols）智能体互联协议**组织多个专业智能体协作，在保证安全底线的前提下提供有温度、有方法的陪伴疏导。

### 1.2 设计目标

1. **安全第一**：高危（自伤/自杀）信号必须 100% 拦截，第一时间给出 24 小时心理援助热线 `400-161-9995`；
2. **智能护航**：接入大模型实时生成个性化回复，断网/超时自动降级模板，保证系统始终可用；
3. **分级处置**：按绿/黄/橙/红四级风险路由不同专业智能体，处置策略逐步升级；
4. **闭环管理**：对话、风险评估、预警、报告全链路落库，教师端可查看四色预警名单并生成 PDF 心理报告。

### 1.3 团队分工

## 二、需求分析

### 2.1 功能需求

| 角色 | 功能点 |
|---|---|
| 学生 | 注册 / 登录；AI 心理陪伴聊天（多轮、可查看历史会话）；匿名发布 / 浏览树洞；查看个人心理报告 |
| 教师 | 登录；查看四色风险预警名单（统计卡片 + 明细表格）；对预警学生一键生成 PDF 心理报告 |
| 管理员 | 登录（管理后台预留）|

### 2.2 非功能需求

- **安全性**：高危信号拦截优先于一切功能；密码与 token 鉴权；数据库参数化查询防注入；.env 敏感配置不入库。
- **稳定性**：LLM 调用失败/超时自动降级模板，保持离线可用；前后端超时配置合理（前端 60s 对齐 LLM 生成耗时）。
- **易用性**：学生端操作零门槛（点开即聊），UI 采用温暖配色与口语化文案。
- **可维护性**：后端分层（路由/数据/风险/智能体），前端组件化 + API 集中封装，全部代码有文档与测试。

### 2.3 四级风险业务规则

| 等级 | 数据库值 | 分数 | 语义 | 处置 |
|---|---|---|---|---|
| 🟢 绿 | low | 0.10 | 情绪积极 / 一般波动 | 共情陪伴 |
| 🟡 黄 | medium | 0.35 | 压力 / 焦虑 / 难过 | 共情 + CBT，匿名关注 |
| 🟠 橙 | high | 0.70 | 受欺凌 / 恐惧 / 被威胁 | 共情 + CBT + 情景导演，通知教师 |
| 🔴 红 | critical | 1.00 | 自伤 / 自杀意念 | 安全评估一票否决，24h 热线 |

## 三、系统架构设计

### 3.1 总体架构

系统采用**前后端分离的分层架构**：表现层（Vue3 前端）、接口层（FastAPI 路由）、数据层（SQLite）与智能体引擎层（ACPs 多智能体协调器），并外接大模型服务。下图用文字描述系统总体分层及一次学生对话的完整数据流：

```text
┌─────────────────────────────────────────────────────────────────────┐
│  ① 表现层：浏览器（Vue3 + Element Plus 单页应用）                     │
│     登录/注册 · AI 陪伴聊天 · 树洞 · 预警名单 · 报告                  │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ ② HTTP/JSON（开发期 Vite Proxy → :8000）
                               ▼
┌─────────────────────────────────────────────────────────────────────┐
│  ③ 接口层：FastAPI（backend/app.py）                                 │
│     认证/会话 | 树洞 | 教师预警 | 报告下载 | 健康检查                   │
│     AI 聊天接口 POST /api/chat/send                                  │
└───────────────┬─────────────────────────────┬───────────────────────┘
                │ ④ 读写                        │ ⑤ 调用
                ▼                             ▼
┌──────────────────────────┐   ┌───────────────────────────────────────┐
│ ⑥ 数据层：SQLite          │   │ ⑦ 智能体引擎层：ACPs 协调器             │
│  student / chat_session  │   │  (ai_agents/coordinator.py)            │
│  chat_message / risk_…  │   │  ① 安全评估 Agent（优先/可一票否决）      │
│  assessment / report /  │   │  ② 按等级路由：共情 / CBT / 情景导演      │
│  user_account / treehole│   │  ③ ACPs/AIP 协商（并行→交叉校验→整合）   │
└──────────────────────────┘   └───────────┬───────────────────────────┘
                                           │ 整合后的统一回复
                                           ▼
                     ┌───────────────────────────────────────────────┐
                     │ ⑧ 大模型：deepseek-v4-flash（OpenAI 兼容 /v1） │
                     │    （未配置/断网/超时 → 规则模板兜底降级）         │
                     └───────────────────────────────────────────────┘
```

**一条普通对话的流转时序（文字描述图）：**

> **学生输入 → 前端 Chat 页 → `POST /api/chat/send` → 后端保存 user 消息到 `chat_message` → 调用多智能体协调器 →（内部）安全评估 Agent 优先判定风险 → 按绿/黄/橙/红路由共情/CBT/情景导演并组织 ACPs/AIP 协商 →（红）直接输出含热线应急话术 /（非红）协调器整合大模型回复 → 后端保存 assistant 消息与 `risk_assessment` 记录 → 返回 `{reply, risk_level, is_vetoed, action, …}` → 前端渲染气泡 + 风险标签。**

### 3.2 前端设计

- **技术选型**：Vue3 组合式 API + Vite 构建 + Element Plus 组件库 + Vue Router（含登录守卫）+ Axios 集中封装（自动带 token、60s 超时、401 自动跳转）。
- **页面结构**：
  - 学生端：`Login` / `Register` / `Home`（功能卡片入口）/ `Chat`（对话区 + 历史会话侧栏 + 风险标签 + 红色应急横幅）/ `TreeHole`（匿名树洞）/ `ReportList`；
  - 教师端：`Login` / `WarnList`（四色统计卡片 + 预警表格 + 生成报告）；
  - 管理员端：`Login`。
- **聊天页关键交互**：消息气泡区分用户/AI，AI 回复携带 `risk_level_cn` 风险标签；`is_vetoed=true` 时展示红色警示横幅与热线；`Enter` 发送、`Shift+Enter` 换行、请求期间禁用输入防重复提交；对 LLM 生成超时给出友好文案区分（而非误报"后端未启动"）。

### 3.3 后端接口设计

统一响应格式：`{"code": 200, "data": …, "msg": "ok"}`；业务失败返回对应 `code` 与中文 `msg`。

| 方法 | 路径 | 功能 |
|---|---|---|
| POST | `/api/student/register` | 学生注册（用户名≥3，密码≥6）|
| POST | `/api/student/login` / `/api/teacher/login` / `/api/admin/login` | 三端登录，返回 token |
| POST | `/api/chat/send` | 发送消息，保存会话并返回回复 + 风险评估 |
| GET | `/api/chat/sessions?student_id=` | 学生历史会话列表 |
| GET | `/api/chat/history?session_id=` | 单会话聊天记录 |
| POST | `/api/chat/sessions/{id}/end` | 结束会话 |
| GET | `/api/treehole/list` / POST `/api/treehole/add` | 树洞列表 / 发布 |
| GET | `/api/teacher/warnings` | 教师四色预警名单 |
| POST | `/api/report/student/{id}` / `/api/report/class` | 生成个体 / 班级 PDF 报告 |
| GET | `/api/report/download?filepath=` | 下载报告 |
| GET | `/health` | 健康检查（含统计与 LLM 接入状态） |

### 3.4 数据库设计

SQLite 文件型数据库 `data/mindisle.db`，共 7 张表，启动时自动初始化并写入 3 个种子账号（student/teacher/admin）。

| 表 | 用途 | 关键字段 |
|---|---|---|
| `student` | 学生信息 | name, gender, age, school, grade |
| `user_account` | 登录账号 | username, password, role, token |
| `chat_session` | 会话 | student_id, started_at, ended_at |
| `chat_message` | 聊天记录 | session_id, role, content |
| `risk_assessment` | 风险评估 | session_id, risk_level, score, indicators |
| `report` | 报告记录 | report_type, title, file_path |
| `treehole` | 匿名树洞 | content, created_at |

设计要点：`ON DELETE CASCADE` 级联清理；`PRAGMA foreign_keys=ON`；所有 SQL 参数化查询防注入；高频查询建索引；时间统一 ISO 8601。

### 3.5 多智能体引擎设计

引擎位于 `ai_agents/` 包，与后端业务解耦、可独立测试：

- `protocols.py`：ACPs/AIP 报文封装（protocol / sender / receiver / msg_type / payload / timestamp…），支持 `to_json / from_json` 序列化往返，为跨进程传输预留；
- `prompts.py`：四类专业智能体 Prompt（安全评估 / 共情陪伴 / CBT / 情景导演），均要求结构化 JSON 输出；
- `coordinator.py`：`MultiAgentCoordinator`——风险评估 → 一级路由 → ACPs/AIP 协商（含一票否决）→ 统一整合；
- `llm.py`：大模型接入层（环境变量配置读取、`chat_completion` 调用、`safe_chat` 降级）。

## 四、多智能体协作与安全兜底机制

### 4.1 北邮 ACPs 协议与 AIP 报文

系统内部智能体之间的通信严格遵循**北邮智能体互联协议（ACPs）**，其中：

- **ARP/ADP**（注册/发现）：各专业智能体在 `protocols.py::AGENT_ROLES` 中统一登记角色，由协调器按需发现与路由；
- **AIP**（交互协议）：规定多智能体并行讨论、交叉校验、修订整合及"一票否决"中断指令的报文格式。

每条 AIP 报文统一封装为标准 JSON（`AIPMessage`），主要字段：

```
protocol   = "北邮智能体互联协议（ACPs）· AIP 交互协议"
version    = "1.0"
message_id = uuid（16 位十六进制）
sender     = coordinator | safety_assessor | empathy_companion | cognitive_behavior | scenario_director
receiver   = 上述角色 或 "all"（广播）
msg_type   = DISCUSS_REQUEST / DISCUSS_RESPONSE / CROSS_CHECK_REQUEST
             / CROSS_CHECK_RESPONSE / REVISION_NOTICE / INTEGRATE_RESPONSE
             / VETO_INTERRUPT / ROUTE_NOTIFY ...
timestamp  = ISO 8601 本地时间
session_id = 会话标识
payload    = {user_text, risk_level, prompt / 建议载荷 / 应急话术 ...}
```

任意报文均可通过 `to_json() / from_json()` 无损序列化与还原，除内存中的协商日志外，也为今后跨进程、分布式智能体接入预留了传输能力。

### 4.2 多智能体路由机制

协调器 `MultiAgentCoordinator.process_dialogue()` 是全部协商的对外主入口，采用"**风险评估驱动的一级路由**"：

```
用户输入 text
    │
    ▼
24h 心理援助热线兜底   ◄─【安全评估 Agent 优先独立运行】
    │                          （backend/risk.py 四级关键词判定）
    ▼
┌──── 风险等级路由表（RISK_ROUTING）────┐
│ 🟢 green : [共情陪伴]                    │
│ 🟡 yellow: [共情陪伴, CBT]               │
│ 🟠 orange: [共情陪伴, CBT, 情景导演]     │
│ 🔴 red   : [安全评估]（一票否决，中断）   │
└──────────────┬───────────────────────────┘
               ▼
ACPs/AIP 协商（非红）：
  协调 → 各专业 Agent 并行讨论（DISCUSS_REQUEST→RESPONSE）
       → 交叉校验（CROSS_CHECK_REQUEST→RESPONSE，黄色及以上进行）
       → 整合（INTEGRATE_RESPONSE 发布统一回复，LLM 生成或模板兜底）
```

每个等级对应的系统动作（`ACTION_MAP`）：绿→`NORMAL_TALK`、黄→`WARN_TEACHER_ANONYMOUS`（匿名关注）、橙→`NOTIFY_TEACHER`（通知心理教师）、红→`TRIGGER_EMERGENCY_POPUP`（应急弹窗）。

### 4.3 安全评估智能体与「一票否决」

安全评估 Agent 是系统内**优先级最高**的智能体，独立于疏导流程运行，并拥有 ACPs 赋予的**一票否决权（veto）**。其工作流程：

1. **独立优先判定**：学生输入先经过 `risk.py::assess()` 关键词规则判定为绿/黄/橙/红；
2. **高危即中断**：一旦命中 🔴（`自杀/不想活/想死/跳楼/割腕…`），协调器立即发送 `VETO_INTERRUPT` 广播中断指令与 `ROUTE_NOTIFY`，**作废其它一切正常疏导输出**，以下四条铁律**无条件执行**：
   - 返回 `is_vetoed=True`、`risk_level=red`；
   - 🔴 级输入**不调用大模型**，直接返回含 `400-161-9995` 的应急话术（README 红线：无论系统是否故障，必须先展示热线）；
   - 前端以红色警示横幅 + `TRIGGER_EMERGENCY_POPUP` 呈现，明确提示立刻拨打热线或求助成人；
   - 自动写入 `risk_assessment` 表（`critical`），并出现在教师端预警名单顶部。
3. **测试保障**：`tests/test_ai_agents.py::test_red_triggers_one_vote_veto` 专门断言——red 输入 `is_vetoed=True`、回复含热线、协作日志包含 `VETO_INTERRUPT` 与 `ROUTE_NOTIFY` 且**没有** `DISCUSS_RESPONSE`（即正常讨论被彻底中断）。

### 4.4 情景导演智能体介入逻辑（橙色风险）

**情景导演（scenario_director）** 是近期接入系统的第四位专业智能体。其设计动机：橙色风险（受欺凌、被孤立、被威胁）仅靠"共情 + CBT 认知分析"不够落地——学生更需要**在一个安全的想象场景中先"演练"如何应对**，从而提升掌控感。逻辑如下：

1. **触发条件**：风险评估为 **orange**（如"被同学欺负""害怕去学校"），路由表即加入 `scenario_director`；
2. **Prompt 能力**：`prompts.py::SCENARIO_DIRECTOR_AGENT_PROMPT` 赋予其"情景导演/儿童戏剧老师"人设——提炼困境 → 改写为 6–18 岁学生能代入的 30 秒小场景 → 提供 2–3 个可当场演练的应对选项 → 明确安全边界；
3. **规则版载荷**：在本轮协商中，情景导演返回结构化建议（`rules`字段），包含：
   - `simulated_scene`（模拟场景：如"课间被取笑起外号"的还原）；
   - `character_roles`（场景角色）；
   - `coping_options`（**应对选项**：平静回应并走开 / 求助班主任或心理老师 / 自我情绪调节）；
   - `role_play_line`（可练习的台词）、`safe_guard`（安全边界）；
4. **协商与整合**：情景导演与共情/CBT 一起参与 `DISCUSS→CROSS_CHECK`，最终由协调器整合进对大模型的统一系统提示（`FINAL_SYSTEM_PROMPT` 已更新为"四位智能体能力"），使 LLM 生成的回复自然涵盖"场景演练 + 求助出口"；
5. **会同步通知教师**：orange 的 `action=NOTIFY_TEACHER`，预警名单中该生标为橙色，教师可一键生成 PDF 报告。

```text
输入：被同学欺负了，很害怕去学校
        │
        ▼  risk.py 命中「欺负 / 害怕」→ orange
        ▼
[共情陪伴] 接住情绪、肯定勇气
[ CBT ]    识别"都是我的错"类认知偏差，给出重建想法
[情景导演]  还原"课间被取笑"场景
           ├─ 模拟场景：课间几位同学取笑你、围观起哄……
           ├─ 应对选项：①平静回应后走开 ②课后告诉老师 ③深呼吸自我安抚
           └─ 安全边界：仅口头演练，不适可求助成人
        ▼  ACPs/AIP 交叉校验与整合
        ▼
协调器统一回复（LLM 生成）：共情 → 场景演练 → 明确"不是你的错"并建议求助成人
        ▼
action = NOTIFY_TEACHER（教师端橙色预警）
```

### 4.5 大模型接入与降级策略

- **接入**：`ai_agents/llm.py` 通过 OpenAI 兼容接口（`base + /chat/completions`）调用 `deepseek-v4-flash`（北邮 myai 平台），`Authorization: Bearer` 加载 `.env::LLM_API_KEY`;
- **多轮记忆**：后端从数据库取当前会话历史，协调器拼装 `system + 最近 8 条 user/assistant + 当前输入` 后请求模型；
- **分级降级（保证离线可用）**：

| 场景 | 行为 |
|---|---|
| 未配置 Key / `LLM_ENABLED=false` | 不发起请求，直接用内置分级模板话术 |
| 网络故障 / 鉴权失败 / 响应异常 / 超时 | `safe_chat` 捕获异常并回退模板，打印警告日志 |
| 🔴 red 高危输入 | **任何情况下都不调大模型**，直接输出含热线的应急话术 |

## 五、系统实现

### 5.1 关键技术实现要点

1. **一票否决铁的执行顺序**：`process_dialogue()` 严格按"空输入兜底 → 风险评估 → 一票否决判定 → ACPs/AIP 协商 → 整合输出"编排；red 分支在任何 LLM 调用之前 return，从代码结构上杜绝高危文本出网；
2. **统一响应契约**：前后端约定 `{code,data,msg}`，`/api/chat/send` 返回 `reply / risk_level / risk_level_cn / risk_score / risk_matched / is_vetoed / action / crisis_hotline`，前端据此渲染风险标签与应急横幅；
3. **多轮记忆**：聊天接口每次从数据库读取会话消息，拼接最近 8 条历史传给协调器，保证对话连贯；
4. **环境隔离**：`app.py` 内实现极简 `.env` 加载器（不依赖 python-dotenv），Key 只进进程环境，`/health` 暴露接入状态便于排查；
5. **Windows 端口管理**：后端为无 `--reload` 单实例（避免多进程抢占 8000 端口；前端 Vite 通过 `/api` proxy 转发）。

### 5.2 前端关键页面实现

- **Chat.vue（核心交互）**：左侧历史会话侧栏（可切换/新建/清空），中间消息流（左 AI 右用户气泡 + 输入加载动画），底部 `el-input` 多行输入框；AI 回复携带 `risk_level_cn` 标签，`is_vetoed` 时展示红色热线横幅；对 LLM 生成超时（`ECONNABORTED`）单独给"生成超时请重试"文案；
- **WarnList.vue（教师预警）**：顶部四张统计卡片（红/橙/黄/需关注总数动态计算），下方 `el-table` 展示学生学号、姓名、等级、分数、命中的关键指标、评估时间，并提供"生成报告"操作；
- **登录守卫**：`router.beforeEach` 白名单（四个登录页）外全部要求 token，未登录自动跳学生登录页；已登录访问登录页按角色重定向。

### 5.3 后端关键接口实现

- **`POST /api/chat/send`**：校验学生 → 复用或新建会话 → 保存 user 消息 → `risk.assess` 先判级 → `orchestrator.process_dialogue(text, session_id, history)` 取回复 → 保存 assistant 消息与 `risk_assessment` 记录 → 组装返回；`is_vetoed = ai_result.is_vetoed or risk.is_critical(level)` 双保险；
- **`GET /api/teacher/warnings`**：遍历学生，取其最近一次风险记录，筛出 medium/high/critical，按 `critical→high→medium` 排序返回，并附中文等级映射；
- **报告生成**：`report.py` 基于 fpdf2 输出中文 PDF（SimHei 字体），支持个体成长 / 班级氛围 / 危机事件三类报告，落盘 `output/` 并记录 `report` 表。

## 七、总结与展望

### 7.1 项目总结

本项目完成了 MindIsle（心屿）学生心理安全评估与多智能体陪伴系统的完整设计与实现：

1. **安全机制闭环**：以"四级风险评估 + 安全智能体一票否决"为核心，高危信号（自伤/自杀）100% 拦截并第一时间展示 `400-161-9995` 心理援助热线，且高危文本在代码层面绝不进入大模型，通过 24 个 pytest 用例与端到端联调双重验证；
2. **ACPs 多智能体体系**：协调器按"并行讨论 → 交叉校验 → 整合输出"组织共情陪伴、CBT、情景导演等专业智能体协作，并全程记录 AIP 协议报文，形成可审计的协商日志；
3. **工程完整度**：Vue3 前端 + FastAPI 后端 + SQLite 数据层 + 大模型接入构成可运行、可测试、可扩展的全栈应用，学生端 / 教师端 / 管理员端三端打通；
4. **稳定性设计**：LLM 断网 / 超时 / 异常自动降级为内置模板，任何网络情况下系统均可正常服务。

### 7.2 不足与改进方向

| 不足 | 改进方向 |
|---|---|
| 风险评估目前基于关键词规则 | 可接入大模型智能评估，与规则双引擎互相校验 |
| 教师端需手动浏览预警名单 | 增加消息推送 / 邮件通知，并按风险升级自动提醒 |
| 情景导演为规则载荷参与协商 | 后续可让每类智能体独立调用大模型，产出更个性化的方案 |
| 无用户侧语音输入 | 接入 ASR（语音转文字）作为倾诉入口 |
| 树洞、报告暂无后台自动归档 | 增加管理后台与管理端页面 |

### 7.3 收获体会

通过本次课程设计，小组成员完整经历了一个真实工程项目的全生命周期：需求分析 → 架构设计 → 分层开发 → 联调测试 → 文档撰写。实践了前后端分离架构、REST API 设计、数据库建模、多智能体协议设计、大模型接入与降级策略、单元测试与端到端测试等方法；同时加深了对 AI 安全意识的理解——面向未成年人的系统，**"安全兜底"永远优先于"功能炫技"**。
